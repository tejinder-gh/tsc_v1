# T-003 — Resolve high-severity dependency advisories

**Source finding:** AUDIT_REPORT.md Phase 0 / CTO §1B | Severity: P1 | Class: BROKEN
**Assigned tier:** SENIOR
**Effort estimate:** 2h | **Sequence:** independent

## WHAT
Resolve the 4 high-severity `npm audit` advisories (transitive through `next@16.1.0`: PostCSS XSS/path-traversal CVEs, `sharp`/libvips CVEs, plus Next.js's own SSRF-via-rewrites and internal-Server-Function-disclosure advisories) by upgrading the affected packages, then verify the app still builds, lints, and passes all tests.

## WHY
`npm audit` (run fresh during this audit) reports 4 high-severity vulnerabilities with fixes available. Two of the Next.js advisories specifically — unauthenticated disclosure of internal Server Function endpoints, and unbounded Server Action payload size in Edge runtime — compound directly with T-001's dashboard finding (Server Actions are exactly what's exposed there), so closing this gap raises the floor under that fix rather than being unrelated hygiene.

## SCOPE — FILES
IN:
- `package.json`
- `package-lock.json`

Notes: `package.json` changes are dependency version bumps only, no script/config changes. `package-lock.json` is the regenerated lockfile from running `npm install` after the bump.

OUT:
- Any application code (`app/`, `components/`, `lib/`, `automations/`) — if the version bump requires code changes to keep the build green, STOP and report BLOCKED rather than adapting code to a breaking change; a breaking upgrade is a bigger, separately-scoped ticket.
- `next.config.mjs` — do not add config to work around an advisory; the fix is the version bump itself.

## ACCEPTANCE CRITERIA
- [ ] AC1: `npm audit --omit=dev` reports 0 high-severity vulnerabilities (moderate/low may remain if no fix is available — note any that can't be closed, with the specific advisory ID, in your final report).
- [ ] AC2: `npm run build` completes with no new errors or warnings that weren't present before the bump.
- [ ] AC3: `npm test` — all 85 tests still pass, no new failures.
- [ ] AC4: `npm run lint` (`biome check .`) still reports clean.
- [ ] AC5: `npm run start` after `npm run build` serves `/` and one `/what-we-automate/[slug]` page successfully (manual smoke check — App Router builds have broken on minor version bumps before; a green build is necessary but not sufficient).

## TEST PLAN
1. `npm audit --omit=dev` before the change — record the baseline (4 high).
2. Apply the version bump (prefer `npm audit fix` first; if it doesn't close the Next.js advisories, bump `next` directly to the patched line in the same major version — check the advisory's "patched versions" field, do not jump a major version).
3. `npm audit --omit=dev` after — confirm 0 high.
4. `npm run build`, `npm test`, `npm run lint`, then `npm run start` + manual smoke check per AC5.

## CONSTRAINTS
- Stay within the `next@16.x` line — do not bump to a new major version; that's an architecture-level decision outside this ticket's scope (App Router major bumps have historically changed caching/data-fetching defaults).
- No new dependencies beyond what the version bump itself pulls in transitively.
- If `npm audit fix` wants to run `npm audit fix --force` (major version bumps for direct deps), do not use `--force` — report BLOCKED with what it wanted to change instead.

## ROLLBACK
`git checkout -- package.json package-lock.json && npm install` restores the prior dependency tree exactly.

## BLOCKED PROTOCOL
If any assumption here proves false against the real code: STOP, write what you found vs. what the ticket claimed, status → BLOCKED. Do not improvise around it.
