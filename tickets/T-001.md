# T-001 — Auth-gate the operator dashboard with Clerk

**Source finding:** AUDIT_REPORT.md CTO §1A | Severity: P0 | Class: MISSING
**Assigned tier:** SENIOR
**Effort estimate:** 4h | **Sequence:** independent

## WHAT
Add [Clerk](https://clerk.com) authentication scoped ONLY to `/dashboard/*`: a sign-in page, a single protected admin account, and middleware that redirects any unauthenticated request under `/dashboard` to sign-in before the page or any Server Action in `app/dashboard/**` can execute. The public marketing site (`/`, `/contact`, `/what-we-automate`, etc.) must remain completely untouched by Clerk — no `ClerkProvider`, no Clerk script/JS, no bundle-size impact outside the dashboard route tree. This was upgraded from a simpler Basic Auth approach at the user's explicit request for a real auth system.

Per file: `middleware.ts` is a new file at the repo root — use Clerk's `clerkMiddleware` with a route matcher limited to `/dashboard(.*)`, every other path must pass through unauthenticated, unchanged. `app/dashboard/layout.tsx` — wrap with `<ClerkProvider>` and Clerk's `<SignedIn>`/`<SignedOut>`/`<RedirectToSignIn>` primitives (or the equivalent current App-Router-idiomatic Clerk pattern), scoped to this layout subtree only, not the root layout. `.env.example` — add the Clerk publishable/secret key env-var names as documentation, values left blank. `package.json` / `package-lock.json` — add `@clerk/nextjs`, the one dependency explicitly authorized for this ticket. `README.md` — a short note that `/dashboard` requires a Clerk account/sign-in and where the keys go.

## WHY
`app/dashboard/layout.tsx` currently has zero auth. `app/dashboard/flows/actions.ts` and `app/dashboard/drafts/actions.ts` expose Server Actions that toggle a client's live automations and send edited outbound SMS/email — reachable by anyone who finds the URL, since `robots.txt` doesn't disallow it either (see T-002). Confirmed via `automations/channels/index.ts:29-47` that `dryRun: true` (both current demo clients) routes sends through a console no-op sender, so there is no active incident today — but this must land before any client is flipped to `dryRun: false`. The user chose a real auth provider over a lighter Basic Auth gate; Clerk was selected as the default for its first-class Next.js App Router middleware support and minimal setup for a single-operator use case. Scoping it tightly to `/dashboard` matters because the audit's Design review already flagged the marketing site's JS bundle as over budget (241.8 KiB vs. a 150 KiB target on `/`) — adding an auth SDK's JS to every public page would make that worse for zero benefit, since the marketing site needs no auth at all.
