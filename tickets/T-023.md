# T-023 — Mark modeled demonstration metrics as illustrative

**Source finding:** AUDIT_REPORT.md §F-08 | Severity: P2 | Class: SUBOPTIMAL
**Assigned tier:** INTERMEDIATE
**Effort estimate:** 2.0 hours | **Sequence:** independent

## WHAT

Ensure that modeled demonstration metrics cannot be read as TheSkillCorner’s measured production outcomes. For the known unverified claims in `demonstration-config.ts`—including active rate limiting, 100% delivery, 450 recipients, and a 54% open rate—replace factual presentation with clearly illustrative labels/values that travel with the scenario step. Preserve the existing top-level demonstration disclaimer and add regression assertions for the specific prohibited factual strings.

## WHY

The product correctly describes demonstrations as illustrative at entry, but exact operational performance claims within the interaction are still easy to mistake for customer evidence. Honest examples are more valuable than invented social proof for a trust-led service sale.

## SCOPE — FILES

IN:
- `lib/journey/demonstration-config.ts` — revise only the identified unverified quantitative/active-state claims and their immediate explanatory copy.
- `lib/journey/__tests__/demonstration.test.ts` — add serialized-registry assertions for the prohibited claims and required illustrative wording.
- `components/journey/demonstration/DemonstrationView.tsx` — only if needed to render a per-step illustrative marker using the existing configuration/disclaimer pattern.

OUT:
- Opportunity diagnosis logic, analytics events, lead capture, and pricing — no product-flow behavior change.
- Verified customer case studies, testimonials, performance claims, or new numbers — none may be invented.
- `app/dashboard/**` — dashboard truthfulness is owned by T-019/T-020.
- Rate-limit implementation or Vercel WAF configuration — external release gate; do not claim it is active in code.

## ACCEPTANCE CRITERIA (testable, binary)

- [x] AC1: Serialized `DEMONSTRATION_REGISTRY` no longer contains the unqualified assertions `rate_limit_active: true`, `100% delivered to inbox`, `450 regional operators`, or `54% open rate`.
- [x] AC2: The revised affected steps visibly use `illustrative`, `example`, or equivalent non-factual wording adjacent to any modeled number/outcome.
- [x] AC3: `DEMONSTRATION_DISCLAIMER` remains rendered in `DemonstrationView` and retains its existing “SIMULATION / SYSTEM DEMONSTRATION” and no-fabricated-performance meaning.
- [x] AC4: The demonstration test fails if one of the prohibited unqualified strings is reintroduced and passes with the corrected content.
- [x] AC5: No new quantitative business result, customer count, delivery rate, or rate-limit status is added.

## TEST PLAN

1. Run `npm test -- lib/journey/__tests__/demonstration.test.ts`; expect exit 0.
2. Run `npm test`, `npm run lint`, and `npx tsc --noEmit`; expect exit 0 after T-022.
3. Inspect one affected scenario in a browser if available; verify the caveat appears alongside the modeled claim. Do not treat this as production performance verification.

## CONSTRAINTS

- Preserve scenario architecture, deterministic selection, and no-private-user-text invariant.
- Use existing editorial/design patterns; no new component library or analytics event.
- Do not remove the whole demonstration or introduce generic legal boilerplate.

## ROLLBACK

Revert the content/test commit. Do not restore unverified metrics without an attached, approved evidence source and an explicit decision to publish it.

## BLOCKED PROTOCOL

If evidence exists that one named metric is measured and approved for publication, STOP and provide the source, date range, owner, and consent status. Do not independently decide it is a case study.
