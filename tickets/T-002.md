# T-002 — Exclude the operator dashboard from crawling

**Source finding:** AUDIT_REPORT.md CTO §1A | Severity: P0 | Class: MISSING
**Assigned tier:** INTERMEDIATE
**Effort estimate:** 0.5h | **Sequence:** independent (pairs with T-001, same finding, does not depend on it)

## WHAT
Add `/dashboard/` to the `disallow` list in `app/robots.ts`, for both the wildcard rule and every named AI-crawler rule, matching how `/api/` and `/dev/` are already excluded.

## WHY
`app/robots.ts` currently disallows `/api/` and `/dev/` but has no rule for `/dashboard/`, so search engines and AI crawlers are free to index and surface an internal operator tool. This is a defense-in-depth measure alongside T-001's auth gate — a crawler will get a 401 either way once T-001 lands, but the URL itself should not be advertised in `sitemap.xml`-adjacent discovery or indexed as content.

## SCOPE — FILES
IN:
- `app/robots.ts`

OUT:
- `app/sitemap.ts` — `/dashboard` routes were never added there; confirm this during implementation but do not add exclusion logic for something that isn't listed.
- `middleware.ts` — the actual access control is T-001's job; this ticket is robots-directive only (a robots.txt disallow is advisory for well-behaved crawlers, not a security boundary).
