# T-008 — Remediate Next.js and Sharp security vulnerabilities

**Source finding:** AUDIT_REPORT.md CTO-01 | Severity: P0 | Class: BROKEN  
**Assigned tier:** SENIOR  
**Effort estimate:** 1.5h | **Sequence:** first — blocks public production deployment

## WHAT
Update the resolved production dependencies to eliminate the identified critical and high-severity CVEs. `next@16.3.0` is affected by `GHSA-2xp9-vwfh-vxw4` and `GHSA-p293-qw3h-jr36`; the minimum patched 16.x release is `16.3.3`. `sharp@0.35.3` is a transitive optional dependency of Next.js and is affected by `GHSA-rgj7-g3m4-5g8c`; the minimum patched release is `0.35.4`.

## WHY
Next.js's built-in image optimization endpoint (`/_next/image`) is publicly accessible and processes user-supplied images. The AVIF processing bug in unpatched Next.js 16 allows unauthenticated attackers to execute arbitrary code on the server, posing a catastrophic risk to production infrastructure and hosted data.

## SCOPE — FILES
IN:
- `package.json`
- `package-lock.json`

OUT:
- Any file in `app/**`, `components/**`, `lib/**`, or `content/**` — this is strictly a dependency remediation ticket. No code modifications are permitted.
- `vitest` major version bump (vitest 5.x is breaking and explicitly deferred).

## ACCEPTANCE CRITERIA
- [ ] AC1: `npm audit --omit=dev` reports 0 Critical and 0 High severity vulnerabilities. If registry access is unavailable, record that boundary and verify the resolved versions against the cited GitHub advisories instead.
- [ ] AC2: `next` resolves to version >= 16.3.3 in `package-lock.json`.
- [ ] AC3: `sharp` resolves to version >= 0.35.4 in `package-lock.json`.
- [ ] AC4: `npm run build` completes without a dependency-caused error. Sandbox port-binding failures are reported as environment-blocked, not as a dependency regression.
- [ ] AC5: `npm test` passes with no regression from the pre-ticket baseline.
- [ ] AC6: No application source is modified. Only `package-lock.json`, and `package.json` if the package range genuinely changes, appear in `git diff`.

## TEST PLAN
1. Run `npm update next` without `--force`; this must refresh Next.js and its transitive optional `sharp` resolution without adding `sharp` as a direct application dependency.
2. Run `npm audit --omit=dev` — verify that Critical and High vulnerabilities are 0.
3. Run `npm run build` — confirm production build succeeds and static generation passes.
4. Run `npm test` — confirm the pre-ticket suite passes without regression.
5. Inspect `git diff --stat` to verify only lockfile/package.json changed.

## CONSTRAINTS
- Do not run `npm audit fix --force` if it introduces breaking major version bumps (e.g., vitest 5.x).
- Maintain Next.js 16 compatibility and Turbopack support.
- Follow established lockfile conventions.

## ROLLBACK
`git checkout -- package.json package-lock.json && npm install`
