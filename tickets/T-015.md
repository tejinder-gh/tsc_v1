# T-015 — Prove production lead delivery before public launch

**Source finding:** AUDIT_REPORT.md CFO-01 / CEO roadmap | Severity: P0 | Class: BROKEN
**Assigned tier:** FOUNDER/OPS
**Effort estimate:** 30 minutes plus provider access | **Sequence:** after T-008; blocks T-013 and public launch

## WHAT

Replace the placeholder `LEAD_WEBHOOK_URL` in the production deployment with a real, approved receiving workflow and perform one controlled end-to-end lead submission. This is an operational configuration task, not a repository change. Do not place the real URL in source control, local transcripts, ticket text, or logs.

## WHY

The checked local `.env` currently contains the documented Zapier placeholder. In production, the lead route intentionally returns 503 when this value is unset; a public form cannot be considered operational until an approved receiver accepts and records a test lead.

## ACCEPTANCE CRITERIA

- [ ] AC1: The production secret store contains a non-placeholder `LEAD_WEBHOOK_URL`; its value is never recorded in this ticket or repository.
- [ ] AC2: A single controlled submission through `POST /api/lead` receives `200 { ok: true, delivered: true }` from the deployed application.
- [ ] AC3: The receiver records the test lead with its `lead_source`, timestamp, and a pre-agreed test marker; the record is then deleted or clearly marked as test according to the receiver's normal process.
- [ ] AC4: A human verifies the customer-facing success state and a safe failure state without exposing lead PII in the evidence.
- [ ] AC5: The provider, deployment environment, test time, and outcome are recorded without secrets or full test-contact details.

## CONSTRAINTS

- Requires action-time user approval before modifying a production secret or creating a real provider workflow.
- Do not use a personal inbox or a real prospect as the test recipient.
- This ticket proves lead delivery only; it does not authorize analytics, email nurture, or a public launch.

## BLOCKED PROTOCOL

If no approved webhook receiver or production deployment exists, status → REQUIRES USER. Do not change the route to accept-and-drop production leads merely to make the site appear ready.
