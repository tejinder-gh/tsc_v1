# T-007 — Fix input-border contrast on the contact form

**Source finding:** AUDIT_REPORT.md Phase 3 (Design) | Severity: P2 | Class: SUBOPTIMAL
**Assigned tier:** INTERMEDIATE
**Effort estimate:** 1.5h | **Sequence:** independent

## WHAT
Introduce a new CSS token for form-input borders (distinct from the existing `--color-line`, which stays as-is for hairlines/dividers/card borders — its correct, intended use per `DESIGN.md`) with a value that meets the WCAG 1.4.11 non-text-contrast threshold of 3:1 against white, and swap it in everywhere `border-line` is currently used specifically for a text-input's border (not for cards, dividers, or hairlines).

## WHY
`DESIGN.md`'s own token table assigns `--color-line` (#DDE3EE) to both "hairline borders/dividers" and, in practice, input borders (`components/forms/ContactForm.tsx`'s `fieldBaseClass`) — but #DDE3EE on white measures 1.29:1, well under the 3:1 threshold WCAG 1.4.11 requires for UI-component borders like form inputs (hairline dividers aren't held to this threshold, which is why the card/divider uses are fine as-is). This was already surfaced and explicitly left open in the same-day design pass (`SUMMARY.md`, "flagged here as a borderline WCAG 1.4.11 call for you to weigh in on") — this ticket resolves it by adding a dedicated, correctly-contrasted token rather than overloading `--color-line` with two different contrast requirements.

In `app/globals.css`, add one new token under `@theme` (e.g. `--color-border-input`); do not change `--color-line`'s existing value. In `components/forms/ContactForm.tsx`, swap `border-line` to the new token in `fieldBaseClass` only (around line 48). In `app/dev/components/page.tsx`, swap the equivalent input example (around line 146) so the internal component gallery reflects the corrected real pattern, per its own stated purpose of mirroring real primitives.

## SCOPE — FILES
IN:
- `app/globals.css`
- `components/forms/ContactForm.tsx`
- `app/dev/components/page.tsx`

OUT:
- Every other `border-line` usage (`app/how-it-works/page.tsx`, `app/results/page.tsx`, `app/dev/components/page.tsx`'s card/section examples, `components/Header.tsx`, `components/Faq.tsx`) — these are cards, dividers, and hairlines, which `DESIGN.md` correctly scopes `--color-line` for and which are NOT held to the 3:1 UI-component threshold. Do not touch these; changing them would be scope creep against a token that is working as designed there.
- `RoiCalculator.tsx`'s form input (line ~173, `border-white/30`) — that's on a dark navy background, a different contrast calculation entirely, and not the finding this ticket addresses.
- `--color-line`'s own defined value in `app/globals.css` — do not change it; a new token is the fix, not a redefinition of the existing one (redefining it would silently change every hairline/card border sitewide, which is explicitly out of scope and would break the card/divider uses that currently work correctly).
