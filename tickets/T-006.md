# T-006 — Configure Neon connection pooler endpoint for serverless scale

**Source finding:** AUDIT_REPORT.md §PHASE 1.2 | Severity: P1 | Class: SUBOPTIMAL
**Assigned tier:** SENIOR
**Effort estimate:** 1.5h | **Sequence:** independent

## WHAT
Update database client connection logic in `lib/second-brain/db/client.ts` and documentation in `.env.example`:
1. Document and validate the Neon `-pooler` connection string (`-pooler.c-7.us-east-2.aws.neon.tech`).
2. Set optimal connection pool options for serverless functions (`max: 5` per lambda instance instead of 10 to avoid connection flooding).
3. Update `lib/second-brain/__tests__/database-ssl.test.ts` to assert that pooler endpoints pass TLS verification and SSL configurations.

## WHY
Under serverless execution on Vercel, dozens of Lambda instances can spin up concurrently. Connecting directly to the Postgres instance quickly exhausts the database's 100-connection limit, causing 500 errors. Using the Neon PgBouncer connection pooler endpoint provides resilient connection sharing.
