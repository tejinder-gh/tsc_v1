# T-004 — Add branded App Router `error.tsx` recovery boundary

**Source finding:** AUDIT_REPORT.md §PHASE 1.3 | Severity: P1 | Class: MISSING
**Assigned tier:** INTERMEDIATE
**Effort estimate:** 1.5h | **Sequence:** independent

## WHAT
Create `app/(marketing)/error.tsx` (and `app/error.tsx` root boundary) matching the editorial design system:
1. Catches unexpected runtime render exceptions inside the marketing layout.
2. Displays an approachable, technical recovery screen (*"An unexpected system exception occurred"*).
3. Provides a "Try again" action (`reset()`) and a direct path to book an audit or contact engineering (`info@theskillcorner.com`).
4. Logs the error to Sentry/telemetry via `captureError(error)` while scrubbing any URL query PII.

## WHY
Next.js without an App Router `error.tsx` boundary renders an unstyled, jarring default error screen when client or server rendering fails. A $200,000 project maintains high-trust visual polish even during unexpected exceptions.

## SCOPE — FILES
IN:
- `app/(marketing)/error.tsx`
- `app/error.tsx`

OUT:
- `app/global-error.tsx` (already exists for root layout; do not modify)
- `app/not-found.tsx` (404 page is working; do not modify)
