# T-004 — Require CRON_SECRET instead of allowing it to fail open

**Source finding:** AUDIT_REPORT.md CTO §1C | Severity: P1 | Class: BROKEN
**Assigned tier:** INTERMEDIATE
**Effort estimate:** 1h | **Sequence:** independent

## WHAT
Change `app/api/cron/route.ts` so that a missing `CRON_SECRET` environment variable causes every request to be rejected (`503`, matching the existing pattern), instead of the current behavior where an unset secret lets any unauthenticated request run a full automation tick.

## WHY
`app/api/cron/route.ts:25` only checks the bearer secret `if (secret && ...)` — if `CRON_SECRET` was never set, the check is skipped entirely and the endpoint runs `runTick()` (which can create drafts and send internal notifications) for any anonymous GET request. `app/api/lead/route.ts` already establishes the correct pattern for this exact situation (missing required prod config → fail loud, not fail open); this ticket brings the cron route in line with that precedent rather than inventing a new one.

- `automations/server/run-tick.ts` and anything under `automations/` — this ticket only changes the auth check at the route boundary, not what the tick does once authorized.
