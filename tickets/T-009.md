# T-009 — Enforce production TLS certificate verification in database client

**Source finding:** AUDIT_REPORT.md CTO-02 | Severity: P1 | Class: SUBOPTIMAL  
**Assigned tier:** SENIOR  
**Effort estimate:** 1.5h | **Sequence:** independent

## WHAT
Update `lib/second-brain/db/client.ts` to enforce strict TLS certificate authority verification on the PostgreSQL connection pool in production environments. Replace the blanket `ssl: { rejectUnauthorized: false }` with an environment-aware SSL configuration that enforces `rejectUnauthorized: true` when `NODE_ENV === "production"` or `VERCEL_ENV === "production"`, while allowing local development connections or explicit overrides via a documented `SECOND_BRAIN_DB_SSL_REJECT_UNAUTHORIZED` environment variable. Add a unit test verifying this configuration behavior across environment scenarios.

## WHY
Disabling certificate verification (`rejectUnauthorized: false`) leaves TLS connections to hosted databases (Neon, RDS, Supabase) vulnerable to man-in-the-middle (MITM) attacks and credential eavesdropping on public or untrusted network hops. In production, database pools handling machine agent credentials and IAM state must verify the database server's identity.

## SCOPE — FILES
IN:
- `lib/second-brain/db/client.ts`
- `lib/second-brain/__tests__/database-ssl.test.ts`

OUT:
- `lib/second-brain/auth/**` — authentication and capability logic must remain untouched.
- `lib/second-brain/repositories/**` — query methods and repository interfaces must not change.
- `app/**` — no route handlers or UI components.

## ACCEPTANCE CRITERIA
- [ ] AC1: When `NODE_ENV === "production"` or `VERCEL_ENV === "production"`, the PostgreSQL connection pool configures `ssl: { rejectUnauthorized: true }` by default.
- [ ] AC2: An explicit environment variable `SECOND_BRAIN_DB_SSL_REJECT_UNAUTHORIZED=false` can override the default in non-standard staging environments if explicitly set.
- [ ] AC3: Development and test environments (`NODE_ENV === "test"` or `"development"`) continue to function without requiring external CA bundles.
- [ ] AC4: New unit test file `lib/second-brain/__tests__/database-ssl.test.ts` covers the SSL configuration logic under production, development, and explicit override flags.
- [ ] AC5: `npm test` passes all 307 existing tests plus the new SSL test suite.
- [ ] AC6: `npm run build` and `npm run lint` pass without errors.
