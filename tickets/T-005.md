# T-005 — Eliminate runtime DDL `CREATE TABLE` from `lib/rate-limit.ts`

**Source finding:** AUDIT_REPORT.md §PHASE 1.2 | Severity: P1 | Class: SUBOPTIMAL
**Assigned tier:** SENIOR
**Effort estimate:** 1.5h | **Sequence:** independent

## WHAT
Refactor `PostgresRateLimiter` in `lib/rate-limit.ts`:
1. Remove `ensureTable()` which runs `CREATE TABLE IF NOT EXISTS public.rate_limits` inside runtime requests.
2. The table and indexes are already created in migration `006_relay_nonces_and_rate_limits.sql` where `skill_corner_runtime` is granted least-privilege DML (`SELECT, INSERT, UPDATE, DELETE`).
3. Make `consume()` directly execute the atomic upsert query without calling `ensureTable()`.
4. Ensure tests in `lib/request-limit.test.ts` pass with zero mock expectation breakages.

## WHY
Runtime web database roles should never possess DDL (`CREATE TABLE`) privileges in production. Attempting DDL on every cold start slows execution and causes caught permission errors against least-privilege database roles.
